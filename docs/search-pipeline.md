# 检索算法：为什么这样设计

本文按数据流顺序解释搜索引擎核心环节的设计动机、公式与权衡。

## 1. 分词：为什么用 GPT-2 BPE？

传统方案需要按语言选分词器：英文按空格+词干化，中文需要 jieba/HRNN 等切词器。本项目的目标是**支持任意 UTF-8 语言**，因此选择 GPT-2 的 BPE（Byte Pair Encoding）子词切分：

- 任何语言的字符串都能确定性地切成子词 id 序列，子词 id 直接充当倒排索引里的"词项"；
- 中英混排、emoji、代码片段统一处理，无需语言检测；
- 子词粒度天然缓解未登录词（OOV）问题。

代价是**子词 ≠ 词**：一个词（如 `Overwatch2`）会被切成多个 token，单词命中只算部分匹配；这也是引入短语挖掘的原因（见下节）。

查询与文档用同一个 tokenizer，id 空间一致，倒排表可以直接求交。

## 2. 短语挖掘：Apriori 风格的逐层连词发现

**动机**：把频繁共现的 token 序列（如"赛博朋克2077"）作为一个整体词项参与检索，避免逐字命中造成的噪声，并给短语加权。

算法（`tokenizer.tokenize_disordered_with_word_count`）：

1. **统计单 token 频次**，频次超过阈值 `T = 2 + max(token_num/250 - 1, 0)` 的 token 作为种子（阈值随语料规模自适应）；
2. **逐层延长**：滑动窗口检查每个种子 token 在语料中的相邻 token，延长后的二元组频次 ≥ T 才保留；再由二元组延展三元组，依此类推——与 Apriori 频繁项集挖掘的"逐层搜索 + 支持度剪枝"同构（k+1 项集频繁 ⇒ 其 k 子串必频繁）；
3. **去包含**：长连词覆盖其子串计数，避免"赛博朋克2077"与"赛博朋克"重复计分；
4. 短语入库 `phrases` 表，查询时（`textproc.extract_phrases`）把查询 token 序列中命中短语表的窗口整体提升为短语词项，并做最长公共子串模糊匹配（阈值 0.95）以兼容形态变体。

> 工程注记：原始实现中种子以标量 `np.int32` 存储而滑窗查找用一元组 key，二者哈希永不相等，导致短语挖掘**静默失效**（`phrases` 表永远为空）。重构时修复为统一的元组键，并有测试断言兜底。

## 3. 倒排索引：标题/正文双路 + 正排

```
title_index:   tokenId → {docUrl: tf}     # 标题命中单独一路，便于加权
content_index: tokenId → {docUrl: tf}     # 正文倒排
stem_df:       tokenId → df               # 文档频率
forward_index: docUrl → 全文 + tf 向量 + 链接关系   # 摘要与展示
```

检索时先按查询词项取倒排表求候选集，再从正排表取展示字段——经典的"倒排定位、正排取内容"。

## 4. 排序模型一：TF-IDF + 余弦（课程原版）

$$w_{t,d} = tf_{t,d} \times \log_2\frac{N}{df_t} / tf_{max,d}, \qquad score(q,d) = \cos(\vec q, \vec d)$$

- `tf / tf_max` 做文档内归一化，防止长文档占优；
- 标题词项额外乘 `TITLE_BOOST=10`（BM25F 思想的简化版：字段级权重）；
- 短语词项乘 `(1 + 2 × 词数)`；
- 文档向量覆盖**文档全部词项**（不只查询词），保证余弦分母（文档模长）正确。

缺点：`tf` 线性增长、无文档长度归一化项，长文档仍占便宜；IDF 用 log2 无饱和效应。

## 5. 排序模型二：Okapi BM25（默认）

$$score(t, d) = idf(t) \times \frac{tf \times (k_1+1)}{tf + k_1\,(1-b+b\,\frac{|d_f|}{avgdl_f})}$$

- `idf = ln(1 + (N - df + 0.5)/(df + 0.5))`：负 IDF 被公式结构规避，稀有词收益饱和；
- 长度归一化项 `(1 - b + b·|d|/avgdl)`：长文档不再线性占优，`b=0.75`；
- `k1=1.5`：词频饱和，重复堆砌关键词的边际收益递减；
- **字段级加权（BM25F 风格）**：标题与正文分别用各自长度归一化打分后加权（标题 ×10），比"把标题 tf 乘 10 混进一个向量"更符合 BM25F 的设计意图；
- `avgdl` 来自 `doc_stats` 集合的全语料聚合（建索引时写入文档长度），而不是候选集近似。

`SCORE_MODE=tfidf` 可切回课程原版算法，便于对比演示。

## 6. PageRank：链接结构重排

文本相关性衡量"内容像不像"，PageRank 补充"页面被多少页面背书"。

实现（`pagerank.py`）：对爬取到的链接图做幂迭代（迭代 30 次，阻尼 `d=0.85`）：

$$PR(p_i) = \frac{1-d}{N} + d\left(\sum_{p_j \in In(p_i)} \frac{PR(p_j)}{|Out(p_j)|} + \frac{DM}{N}\right)$$

- 指向语料外（未爬取页面）的边忽略；
- **dangling 节点**（无出边）的质量均匀回流到全图（`DM` 项），避免秩泄漏；
- 收敛后按最大值归一化到 (0,1] 存入正排表；
- 最终排序：`final = relevance × (1 + PAGERANK_WEIGHT × PR)`——乘法融合保证"完全不相关"的页面不会被链接结构抬进结果，同时让同等相关性的页面按权威性排序。

## 7. 缓存与失效

- DF 表、短语表、语料文档数在进程内（或 Redis）缓存：搜索路径零额外扫描；
- 每轮索引批次结束后统一失效（`Database.invalidate_corpus_caches`）——修正原版"爬完新内容后 `file_num` 缓存不失效导致 IDF 用旧语料规模"的问题；
- Redis 未配置时自动降级为进程内 TTL 缓存，本地开发零依赖。
